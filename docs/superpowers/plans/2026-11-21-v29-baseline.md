# V29 baseline implementation plan

Goal: a versioned strict 3D mission environment and an observation-only classical
baseline with seeded diagnostics, before adding a learned residual.

Spec: ../specs/2026-11-21-hybrid-3d-landing-design.md

Architecture: retain V28 behavior through default extension hooks; V29 overrides
physics-contact sampling, settling, deadlines and reward. Its controller consumes
only the existing 16-value observation and nominal vehicle constants. The audit
runner passes the same delayed/noisy observations that a policy receives.

Constraints: radius 0.5 m; impact <=1 m/s; tilt <=10 degrees; three contacts;
speed <=0.1 m/s and angular rate <=0.1 rad/s for 0.5 s; mission deadline 20 s.
Do not commit or push without a user request. Preserve unrelated workspace files.

Review focus: false success after bouncing; body/world frame signs; yaw-invariance;
mission deadlines accidentally bootstrapped; measurement noise at touchdown.

Tasks:
- [x] Write failing unittest regressions for strict success and controller inputs.
- [x] Add minimal legacy extension hooks and versioned strict environment.
- [x] Implement observation-driven cascaded control with phase diagnostics.
- [x] Run seeded clean baseline (200 episodes, >=99% precise gate).
- [x] Run noisy/delayed and full-envelope diagnostics; publish measured results.
- [x] If clean gate passes, create bounded residual interface and tests; defer
      long training until the noisy baseline and reward checks justify it.

Verification: unittest discovery plus recorded seeded baseline CSV/JSON outputs.
Use the existing temporary MuJoCo test interpreter if it remains functional.
If a gate fails, diagnose and report the failure without promoting the stage.

Execution ledger:
- Plan created; design approval given by user ('start').
- First suite: 8 tests passed; extended suite: 20 tests passed, including review
  regressions for repeated impacts, tilt, transient hull contact and sensor seed.
- First clean gate passed 200/200; after independent review tightened substep
  semantics, rerunning the full clean gate before recording final results.
- Ruling: implement only the baseline and residual boundary in this milestone;
  long RL training remains behind the design's reward/diagnostic gates. This
  avoids spending Colab time on an unvalidated reward as happened with V28.
- Independent review found five correctness issues; all received fixes and
  regression checks. No commits or pushes performed.
- Second review identified recovery from contact loss and nominal parameter/period
  propagation in the residual interface; both reproduced failing, then fixed.
- Final verification: 22 tests passed; SB3 checks passed for mission and delayed,
  noisy residual env. Final source version rerun: clean 200/200, delay 50/50,
  full envelope 39/50 (7 TIMEOUT, 4 SAFE_OUTSIDE, no crashes). Clean Wilson lower
  bound is 98.12%, so this is a development gate, not proof of 99% reliability.
- Saved source hashes, configurations and results in docs/v29_baseline_results.json.
  Colab notebook structure validated; Colab execution and residual training unrun.
